# SwiftUI 项目规范

适用于本项目 SwiftUI View 的创建、修改和审查。编写和 review 使用同一份规范；`AGENTS.md` 和相关技能只提供读取入口。

## SWIFTUI-01：View 拆分与 body 结构

- 使用职责单一的小 View 组合界面，让 `body` 表达页面或组件的整体结构。多个独立区域、复杂条件分支或较长的动作处理挤在一起，影响理解时，应按职责拆分。
- **独立的子 View**：可复用、具有独立界面含义，或需要明确数据与状态边界的组件，拆成单独的 `View`。名称体现职责，只接收自身渲染和交互所需的最少数据。
- **私有属性或函数**：仅服务当前页面、简单且一次性的布局片段，可以用命名清晰的 `private var` 或 `private func`。不依赖参数的片段通常用计算属性，需要参数的片段可以用构建函数。不要为了缩短 `body`，把整段复杂页面原样搬进一个大函数。
- 将较长的动作处理或计算移出布局表达式，使用有明确用途的函数或已有业务层，避免在 `body` 中混杂布局和业务处理。
- 不设固定的 `body` 行数门槛，不要求每个简单布局都新建一个 View 或文件。审查时说明混杂了哪些职责、为何难以理解，以及合适的拆分边界，不能仅凭行数或个人偏好要求改写。

本项目明确允许上述简单私有属性／函数。通用 SwiftUI 技能中“统一拆成独立 View”的建议与这里不一致时，遵循本项目规范。

## SWIFTUI-02：展示常量

- 使用嵌套在对应 View 内的 `private struct Constants`，集中管理仅供该 View 使用的间距、内边距、尺寸、圆角、透明度等展示常量。
- 业务数据，以及 `.tint`、`.secondary`、`.headline` 等具有明确系统语义的样式，不放入 `Constants`。
- 用户可见文案遵循[文案与本地化规范](Localization.md)，不放进 View 的 `Constants` 或局部字面量。

## 验证与维护

- 源码审查确认职责划分、组件输入和常量归属。仅调整文档时无需构建 App。
- 实际重构 View 时，根据受影响行为验证布局、状态更新和交互；不把 `body` 变短本身当作正确性或性能证明。
- 新增项目约定时，在本文件写明适用范围、要求、例外和验证方式。通用 API、可访问性和性能指导继续按需读取专项技能，避免在这里复制整份指南。

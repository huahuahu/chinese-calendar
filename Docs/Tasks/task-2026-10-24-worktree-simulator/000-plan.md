# 工作区模拟器分配：方案

- 状态：可执行
- 更新日期：2026-10-24
- 依据：[Xcode 工作流](../../agent-workflows.md)、[通用规范](../../Conventions/Common.md)

## 目标与范围

以当前工作区 `.xcodebuildmcp/config.yaml` 为准，检查同一 Git 仓库登记的其他 worktree 是否引用相同模拟器 UUID。有冲突时，新建同型号、同 runtime 的空白模拟器，只更新当前工作区配置；没有冲突时复用。

这里的“使用”指配置引用，不代表操作系统能检测某个 Agent 当前是否正在操作设备。暂不实现跨独立仓库扫描、运行期设备租约、设备删除或数据克隆。

## 方案

- 新增 Python 3.9+ 脚本 `Scripts/ensure_worktree_simulator.py`，支持 `--worktree` 和 `--dry-run`。YAML 使用 `Scripts/requirements.txt` 固定版本的 PyYAML；CI 显式选择 Python 3.12 并安装同一份依赖。
- 使用 Git common directory 中的文件锁覆盖检查、创建和原子写回。同一仓库的并发分配串行执行；锁由操作系统随进程退出释放。
- 使用 `simctl` 完成脚本内设备查询与创建；当前 MCP 未暴露模拟器创建接口。保留原设备及其运行状态，不启动新设备。
- 已有 UUID 无效或不可用时明确报错，避免悄悄切换到其他型号或系统。新工作区没有本机配置时，从版本控制中的 `config.example.yaml` 初始化；模板仅指定通用设备型号，不包含本机 UUID。
- 本机 `config.yaml` 保留在磁盘，从 Git 索引移除并加入 `.gitignore`。不使用 `assume-unchanged` 或 `skip-worktree`。
- 工作区初始化、普通本地测试/构建、截图测试，以及 Agent 操作前使用同一个分配入口；CI 保留 runner 设备选择规则。

## 验收标准

| ID | 场景 | 验证方式 |
| --- | --- | --- |
| AC-01 | 无冲突时不创建设备，不改已有配置 | 隔离集成测试、真实重复运行 |
| AC-02 | 有冲突时创建同型号同 runtime 设备，仅更新当前配置 | 隔离集成测试、当前工作区实测 |
| AC-03 | dry-run、创建失败、无效设备不会改写配置 | 隔离集成测试 |
| AC-04 | 并发调用不会重复分配，其他 worktree 的配置保持原样 | 多进程集成测试 |
| AC-05 | 缺失本机配置可从模板初始化；真实配置不再被跟踪 | 集成测试、Git 索引及忽略规则检查 |
| AC-06 | 本地脚本和文档采用统一入口，CI 不依赖本机 UUID | 源码检查、脚本语法检查 |
| AC-07 | Python 实现不再依赖 Ruby，CI 显式安装所需依赖；缺依赖时明确失败 | 干净虚拟环境安装、集成测试及工作流检查 |

## 方案调整

2026-10-24：初版使用 Ruby 标准库以避免额外 YAML 依赖。用户指出项目及 CI 需要统一使用 Python，明确要求迁移；因此替换实现和全部调用入口，保留原有设备分配行为，并显式管理 PyYAML 依赖。

# 历史页原生三栏：方案

- 状态：可执行
- 更新日期：2026-10-22
- 依据：[导航规范 NAV-07](../../Conventions/Navigation.md)、[SwiftUI 规范](../../Conventions/SwiftUI.md)、[本地化规范](../../Conventions/Localization.md)
- 前置架构：[Issue #146 分栏与详情栈](../issue-146-navigation-containers/000-plan.md)

## 背景、目标与范围

将正式历史 Tab 的「正统时间线 → 朝代资料入口 → 具体内容」组织为原生三栏 `NavigationSplitView`。左栏选择正统时期，中栏选择皇帝、年号或正统时间跨度，右栏显示原有内容并保留详情内的继续导航。宽窗口展开分栏，窄窗口共用同一结构折叠浏览。

## 方案与决策

- 沿用 App 组合原生分栏、NavigationCore 管理最后一栏单栈的边界，不新增 SDK 容器模型。
- 历史 Tab 使用所在层 `.scope(.history)` 详情栈；独立历史容器使用 `.primary`。容器通过 Destination 构建，详情根与 push 均由现有配置构建。根层与模态共享接入方式。
- 正统时期身份保留 `orthodoxPeriodID`，不能以 `dynastyID` 替代。使用明确的空态与历史详情根路由，选择从详情根投影。App 保存栏显示和紧凑布局偏好。
- 切换时期清除旧资料选择与详情路径；切换资料替换详情根并清空路径；重复选择同一项保留路径。变更先经 Context 权限检查，拒绝后保持原状态。
- 深链接沿用现有确认和真实关闭协调。只有请求实际应用后同步分栏；皇帝入口从当前数据库解析父级时期，不能在等待确认时提前改变历史选择。
- 复用现有皇帝、年号与正统时间页面及独立朝代详情入口。空态文案统一放在本地化模块。

## 待定事项与后续调整

初始进入保持未选择状态；不自动选择某朝代或某资料。具体交互若暴露系统折叠行为差异，记录修正和实际证据。

2026-10-22 交互修正：初次实现将皇帝链接解析为皇帝列表根并补入皇帝详情 path；iPhone 实际打开后停在列表，未显示目标详情。改为带父级时期身份的 `.historyEmperor(orthodoxPeriodID:emperorID:)` 稳定详情根，直接显示皇帝目标，前两栏从此根投影选择。皇帝详情返回资料入口，点击帝王入口可打开现有只读列表。该调整保留原有深链接目标，不增加 Core 容器机制、额外 selection 或延时协调。

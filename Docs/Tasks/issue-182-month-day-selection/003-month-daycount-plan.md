# 真实月长与累计日期定位

- 日期：2026-10-25
- 状态：可执行；用户已明确授权三项修改。
- 接续：[原方案](000-plan.md)。本补充替代其中使用 Foundation 农历定位今天的决定。

## 方案

1. 丙辰年（236）十二月的实际区间为 28 天。保留上游所选历算口径，修复大小月标记转回天数时丢失特殊月长的问题；同步逐日源数据、月表和基础 SQLite 制品。源数据争议见上游 `calendar.js` 的 237 年二月注释，不把本次修正作为独立历史考证。
2. `dayCount` 表示完整月份的实际长度；正数且小于 30 为小月，30 为大月。数据集首尾缺失的日记录不缩短月份本身。
3. 按 `lunarMonthIndex` 排序，从月序 0 的月初 JDN 1640700 累计 `dayCount`，以半开区间定位目标日。该锚点由数据集首日 JDN 1640703、月内初四推出。月序缺口、无效月长和范围外目标不能产生猜测结果。
4. 有真实日记录时保留精确日选择；缺日时用累计区间落到真实月。首页直接表达“今天”，不再先向系统请求农历年份。年、月标签和闰月身份来自数据库。

## 验收

- 23、28、29 显示小月，30 显示大月；非正数及超过 30 的月长无效。
- 完整源数据 884256 天，逐日验证累计定位的月序和月内日号；除数据覆盖首尾外，逐日数量与真实月长相符。
- 验证 28 天月末／次月初、同年重复月名、闰月、跨年、缺失月份和范围外日期。
- 核对基础 SQLite 月表与完整源数据相同；本次不发布远程 full 制品。

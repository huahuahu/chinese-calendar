## 已修复问题的对照证据

1. 03、04：初版 `alert(isPresented:presenting:)` 在 2020 提示上收到 2021 后仍显示 2020。旧确认 ID 防护阻止误跳，但点击旧确认只关闭提示，最新请求没有再次展示。
2. 10、11：第一次切换到 Identifiable item 提示后文案替换成功，但系统先写回 nil 导致请求被取消，确认只收起提示、保留选择器。单请求批准也复现。主 Agent 将消费请求限定到显式带 ID 的按钮动作后，13–19 通过。
3. 12：选择器在冷启动 2026、2024 深链之后、关闭重开时均停在公元前 221 年列表起点，未进行任何手动滚动。等待首次有效滚动几何后定位的修复安装后，20–24 通过。

## 工具与数据边界

- 原生会话前期多次出现 `Session not found`。重新创建会话并激活已安装 App 后恢复；这是会话工具问题，未归因为 App 缺陷。
- 最后两轮均由原生 `DeviceInteractionInstallAndRun` 返回 `Application installed and running`，随后检查了真实 App hierarchy 与稳定截图。
- 快速捕获偶尔处于转场中；正式截图通常追加空捕获后保存。连续 alert 替换中间短暂显示父页面，随后新提示出现，最终以稳定的新文案和落地日期确认。
- 没有清空已下载数据，没有替换/删除完整日期库。运行日志记录 `Keeping installed full seed store instead of reinstalling bundled base store`。
- UI 无法在提示替换的瞬间确定性调用已经失效的旧按钮闭包；旧确认、旧 scope 的异步 ID 防护以主 Agent 的 Core 状态测试为补充，不能由该 UI 流程单独证明。

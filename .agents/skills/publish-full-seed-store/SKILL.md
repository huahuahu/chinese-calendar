Publish a new remote `full` SwiftData seed store for this repository.

Use this skill when the user asks to publish, release, upload, or refresh the full SQLite seed store that includes day-level calendar data. The repository also ships a small bundled `base` store; this workflow is only for the remote `full` store.

## Inputs

- Optional dataset version in `YYYY.MM.DD` format.
- If no dataset version is provided, infer it from the current local date.
- Optional release tag. Default: `full-seed-store-<datasetVersion>`.
- Optional release title. Default: `Full seed store <datasetVersion>`.
- Optional release notes. Include the generated byte count and SHA-256.

## Workflow

1. Resolve repository paths:
1. Repository root: `/Users/tigerguo/git/Chinese-date`
1. Import input: `Data/Processed/swiftdata_import`
1. Full store output: `Data/Processed/remote_full_seed_store`
1. Store file: `Data/Processed/remote_full_seed_store/ChineseCalendar.sqlite`
1. Runtime manifest from builder: `Data/Processed/remote_full_seed_store/manifest.json`
1. Remote manifest to upload: `Data/Processed/remote_full_seed_store/ChineseCalendarFullSeedStoreManifest.json`
1. Validate the processed import artifact before building:
1. Run `Scripts/DataSchemas/validate_swiftdata_import.swift --input Data/Processed/swiftdata_import`.
1. Rebuild the full seed store into `Data/Processed/remote_full_seed_store`.
1. Remove the output directory first to avoid publishing stale sidecar files or stale manifests.
1. Build with `--content-level full`.
1. Verify the output directory contains `ChineseCalendar.sqlite` and no SQLite sidecar files.
1. Compute the SQLite byte count and SHA-256.
1. Resolve the app-supported schema version from `ChineseCalendarFullSeedStoreInstaller.supportedSchemaVersion`.
1. Generate `ChineseCalendarFullSeedStoreManifest.json` with:
1. `datasetVersion`
1. `schemaVersion`
1. `seedStoreContentLevel: "full"`
1. `seedStoreFormatVersion: 4`
1. `storeFileName: "ChineseCalendar.sqlite"`
1. `byteCount`
1. `sha256`
1. `downloadURL` pointing at the GitHub release asset.
1. Create a GitHub release for the new tag and upload both:
1. `ChineseCalendar.sqlite`
1. `ChineseCalendarFullSeedStoreManifest.json`
1. Update the tracked manifest URL in `project.yml` to the new tag.
1. If local generated `Apps/iOSApp/Info.plist` or `Apps/macOSApp/Info.plist` files exist, update them for local testing, but remember they are ignored and are not the source of truth.
1. Verify the release after upload:
1. `gh release view <tag>` shows both assets.
1. The SQLite asset size equals the local `byteCount`.
1. The remote manifest asset exists.
1. Run `swift test --package-path Sources` after tracked source/config changes.

## Guardrails

- Do not publish the temporary SQLite generated only for size checks; always publish from `Data/Processed/remote_full_seed_store`.
- Do not overwrite, delete, or replace assets on an existing release unless the user explicitly asks for an overwrite.
- Do not push source-code branches or create PRs unless the user asks. Publishing the GitHub release asset is separate from committing the manifest URL update.
- Do not commit files under `Data/Processed/remote_full_seed_store`; that directory is ignored and contains release artifacts, not source data.
- Keep the bundled `base` store at `Apps/Shared/Resources/ChineseCalendarSeedStore.bundle` separate from the remote `full` store.
- Use the local proxy environment for all network commands (`gh`, `curl`, `git push`, etc.).
- For GitHub release commands, target the default branch (`main`) unless the user specifies another target.
- If release creation times out or appears hung during the large SQLite upload, check `gh release view <tag>` before retrying; the manifest may upload before the SQLite asset.

## Suggested command sequence

```bash
set -euo pipefail

REPO_ROOT="/Users/tigerguo/git/Chinese-date"
DATASET_VERSION="${DATASET_VERSION:-$(date +%Y.%m.%d)}"
TAG="${TAG:-full-seed-store-$DATASET_VERSION}"
TITLE="${TITLE:-Full seed store $DATASET_VERSION}"
INPUT_DIR="$REPO_ROOT/Data/Processed/swiftdata_import"
OUTPUT_DIR="$REPO_ROOT/Data/Processed/remote_full_seed_store"
STORE_FILE="$OUTPUT_DIR/ChineseCalendar.sqlite"
REMOTE_MANIFEST="$OUTPUT_DIR/ChineseCalendarFullSeedStoreManifest.json"
DOWNLOAD_URL="https://github.com/huahuahu/chinese-calendar/releases/download/$TAG/ChineseCalendar.sqlite"
MANIFEST_URL="https://github.com/huahuahu/chinese-calendar/releases/download/$TAG/ChineseCalendarFullSeedStoreManifest.json"
PROXY_ENV=(
  HTTP_PROXY=http://127.0.0.1:1082
  HTTPS_PROXY=http://127.0.0.1:1082
  ALL_PROXY=http://127.0.0.1:1082
  http_proxy=http://127.0.0.1:1082
  https_proxy=http://127.0.0.1:1082
  all_proxy=http://127.0.0.1:1082
  NO_PROXY=localhost,127.0.0.1,::1
  no_proxy=localhost,127.0.0.1,::1
)

cd "$REPO_ROOT"

Scripts/DataSchemas/validate_swiftdata_import.swift --input "$INPUT_DIR"

rm -rf "$OUTPUT_DIR"
mkdir -p "$OUTPUT_DIR"

swift run -c release --package-path Scripts/BuildChineseCalendarSeedStore ChineseCalendarSeedStoreBuilder \
  --input "$INPUT_DIR" \
  --output "$OUTPUT_DIR" \
  --content-level full \
  --save-interval 5000

test -f "$STORE_FILE"
if compgen -G "$STORE_FILE-*" >/dev/null; then
  echo "Unexpected SQLite sidecar files remain in $OUTPUT_DIR" >&2
  ls -la "$OUTPUT_DIR" >&2
  exit 1
fi

BYTE_COUNT="$(stat -f '%z' "$STORE_FILE" 2>/dev/null || stat -c '%s' "$STORE_FILE")"
SHA256="$(shasum -a 256 "$STORE_FILE" | awk '{print $1}')"
SCHEMA_VERSION="$(sed -n 's/.*supportedSchemaVersion = "\([^"]*\)".*/\1/p' Sources/ChineseCalendarPersistence/ChineseCalendarFullSeedStoreInstaller.swift | head -n 1)"

if [[ -z "$SCHEMA_VERSION" ]]; then
  echo "Unable to resolve supported schema version." >&2
  exit 1
fi

node - "$REMOTE_MANIFEST" "$DATASET_VERSION" "$SCHEMA_VERSION" "$BYTE_COUNT" "$SHA256" "$DOWNLOAD_URL" <<'NODE'
const fs = require("fs");
const [
  output,
  datasetVersion,
  schemaVersion,
  byteCount,
  sha256,
  downloadURL
] = process.argv.slice(2);

const manifest = {
  datasetVersion,
  schemaVersion,
  seedStoreContentLevel: "full",
  seedStoreFormatVersion: 4,
  storeFileName: "ChineseCalendar.sqlite",
  byteCount: Number(byteCount),
  sha256,
  downloadURL
};

fs.writeFileSync(output, `${JSON.stringify(manifest, null, 2)}\n`);
NODE

if env "${PROXY_ENV[@]}" gh release view "$TAG" >/dev/null 2>&1; then
  echo "Release already exists: $TAG. Refusing to overwrite assets." >&2
  exit 1
fi

env "${PROXY_ENV[@]}" gh release create "$TAG" \
  "$STORE_FILE" \
  "$REMOTE_MANIFEST" \
  --target main \
  --title "$TITLE" \
  --notes "Full SwiftData seed store with day-level calendar data.

- Dataset version: $DATASET_VERSION
- Schema version: $SCHEMA_VERSION
- Seed store format version: 4
- Byte count: $BYTE_COUNT
- SHA-256: $SHA256"

env "${PROXY_ENV[@]}" gh release view "$TAG" \
  --json tagName,name,assets,url \
  --jq '{tag:.tagName,name:.name,url:.url,assets:[.assets[]|{name:.name,size:.size,url:.url}]}'

python3 - "$TAG" "$MANIFEST_URL" <<'PY'
import pathlib
import sys

tag, manifest_url = sys.argv[1:]
project = pathlib.Path("project.yml")
text = project.read_text()
old = "https://github.com/huahuahu/chinese-calendar/releases/download/full-seed-store-"
lines = []
for line in text.splitlines():
    if "ChineseCalendarFullSeedStoreManifestURL:" in line and old in line:
        prefix = line.split("ChineseCalendarFullSeedStoreManifestURL:", 1)[0]
        line = f"{prefix}ChineseCalendarFullSeedStoreManifestURL: {manifest_url}"
    lines.append(line)
project.write_text("\n".join(lines) + "\n")
PY

swift test --package-path Sources
```

## Output expectations

Report:

1. Release tag.
1. Uploaded SQLite byte count and SHA-256.
1. Remote manifest URL.
1. Whether `project.yml` was updated.
1. Validation and test results.
